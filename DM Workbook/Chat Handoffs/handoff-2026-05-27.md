### 2. Frontend Fixes - `CharacterNew.js`

All changes are in `dndclient/src/pages/characters/CharacterNew.js`.

#### Subrace Picker
- Added `raceGroup` field to all 4 entries in `dndAPI/seeds/races.json` (`"Human"`, `"Elf"`, `"Dwarf"`, `"Halfling"`)
- Added `raceGroup` to the compendium bootstrap projection in `dndAPI/DataAccess/compendium.js`
- Race step now shows a base-race select (unique groups, alphabetically sorted) and a subrace select that only appears when the selected group has more than one variant
- `raceGroupId` is UI-only state - not sent to backend. `raceId` still stores the specific variant (e.g. `high-elf`) which is what the derivation engine already uses
- Changing race group auto-resets `raceId` to the first subrace in the new group

#### Alphabetical Sorting
- Race groups sorted via `localeCompare` in `getRaceGroups()`
- Subraces within each group sorted via `localeCompare` in `sortedRacesForGroup()`
- Classes sorted in the Class step render
- Subclasses sorted in the derived `subclassOptions`

#### Alignment Dropdown
- Added `ALIGNMENTS` constant (all 9 standard alignments)
- Replaced free-text `<input>` with a `<select aria-label="Alignment">` in the Background step
- Alignment value persists to the Review step and is submitted to the backend unchanged

#### Ability Score Methods
- Added `SCORE_METHODS` constant (`standard`, `pointBuy`, `roll`)
- Added `STANDARD_ARRAY`, `POINT_BUY_COSTS`, `POINT_BUY_BUDGET`, `POINT_BUY_MIN`, `POINT_BUY_MAX` constants
- Added `rollAbility()` function (4d6 drop lowest)
- New handlers: `adjustPointBuyScore()`, `rollScore()`, `rollAllScores()`, `changeScoreMethod()`
- `changeScoreMethod()` resets scores to appropriate defaults (all 8s for Point Buy, Standard Array values for others)
- Ability Scores step now shows a method toggle group with three buttons:
  - **Standard Array** (default): free numeric inputs pre-filled with 15/14/13/12/10/8
  - **Point Buy**: +/- controls, scores locked 8-15, PHB cost table, live budget display (27 points)
  - **Roll**: Reroll per ability + Roll All button, scores displayed as text (not inputs)
- `scoreMethod` is local UI state only - not sent to the backend. `baseAbilityScores` is what gets submitted regardless of method.

## Notes for Next Claude

- The `raceGroup` field in `races.json` is the only data schema change. The backend derivation engine (`characterDerivation.js`) uses `raceId` to look up the race - no change needed there. `raceGroupId` is wizard UI state only.
- Point Buy and Roll methods produce final `baseAbilityScores` that are submitted to the backend the same way as Standard Array. The method chosen is not persisted.
- The `POINT_BUY_COSTS` table only covers scores 8-15. If a score outside that range somehow gets into Point Buy mode (e.g. switching from Standard Array at value 16), the `??` fallback in `adjustPointBuyScore` returns 0 cost for out-of-range values. This is acceptable for now but worth noting.
- `CharacterNew.js` was corrupted once during this session by a bash `cat >>` operation that duplicated the file tail. It has been fixed. If the file ever looks truncated or has duplicate closing braces, check lines 710-715.
